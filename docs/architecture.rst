Архитектура приложения
======================

Общая схема
-----------

Game Master Hub — настольное (десктопное) приложение, которое работает на одном
компьютере с локальной базой данных. Выбрана многослойная (трёхуровневая)
архитектура. Каждый уровень — отдельный пакет Python, и зависимости идут только
сверху вниз:

.. code-block:: text

   +--------------------------------------------------------------+
   |  gm_hub.ui      уровень представления: окна PySide6 (Qt)      |
   |  (app, common, table, gm_window, player_window, ...)         |
   +------------------------------+-------------------------------+
                                  | вызывает функции
   +------------------------------v-------------------------------+
   |  gm_hub.logic   бизнес-логика: правила системы, проверки     |
   |  (auth, games, signups, characters, notes, ...)              |
   +------------------------------+-------------------------------+
                                  | параметризованные SQL-запросы
   +------------------------------v-------------------------------+
   |  gm_hub.db      уровень данных: SQLite (файл gm_hub.db)      |
   |  (database.py, schema.sql)                                   |
   +--------------------------------------------------------------+

Главные правила, которых придерживается код:

* **логика не знает об интерфейсе** — модули ``gm_hub.logic`` не импортируют
  PySide6, поэтому все правила проверяются автотестами без окон;
* **окна не содержат SQL** — интерфейс только вызывает функции логики и
  показывает результат;
* **SQL — только параметризованный** (знаки ``?``), поэтому SQL-инъекции
  невозможны; каждое изменение данных выполняется в транзакции ``with conn:``;
* **ошибки — исключения двух видов**: ``ValidationError`` (неверный ввод или
  нарушение правила) и ``AccessError`` (действие недоступно роли); окна ловят
  их и показывают понятное сообщение.

Паттерн проектирования
----------------------

Разделение близко к MVC: модель — база данных и функции ``logic``,
представление — виджеты и таблица стилей Qt, контроллер — классы окон и вкладок
(например, ``ScheduleTab``), которые принимают действия пользователя и вызывают
логику. Общая основа всех вкладок — класс ``Tab`` и окна кабинета ``MainFrame``;
защита от потери несохранённых правок вынесена в добавку ``FormGuard``.

Состав пакетов
--------------

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Модуль
     - Назначение
   * - ``main.py``
     - точка входа: журнал ошибок, создание ``QApplication``, открытие БД и главного окна
   * - ``gm_hub.config``
     - пути к файлам (БД, журнал), форматы даты и времени
   * - ``gm_hub.settings``
     - настройки на компьютере в файле ``settings.json``: тема, запомненные логины, последняя вкладка, размер окна, крупный текст
   * - ``gm_hub.db.database``
     - подключение к SQLite, создание таблиц из ``schema.sql``, добавление столбцов при обновлении
   * - ``gm_hub.logic.auth``
     - регистрация, вход, профиль, удаление аккаунта, хэширование паролей
   * - ``gm_hub.logic.games``
     - игровые сессии: создание, изменение, отмена, удаление, свободные места, итоги, статистика
   * - ``gm_hub.logic.signups``
     - заявки: подача, подтверждение, отклонение, отзыв, очередь, новые решения, экспорт участников
   * - ``gm_hub.logic.characters``
     - персонажи Игрока и повышение уровня после игры
   * - ``gm_hub.logic.notes``
     - сюжетные заметки к сессиям и база знаний мира, поиск
   * - ``gm_hub.logic.month``
     - вспомогательные расчёты для календаря месяца
   * - ``gm_hub.logic.dice``
     - броски кубиков d4–d20
   * - ``gm_hub.ui.app``
     - главное окно, переключение экранов, тема, профиль, обработка ошибок
   * - ``gm_hub.ui.common``
     - общие элементы: карточки, плашки, таблетки, окно кабинета со вкладками, диалоги
   * - ``gm_hub.ui.table``
     - таблица строк в стиле макетов (``RowTable``)
   * - ``gm_hub.ui.style`` и ``gm_hub.ui.theme``
     - таблица стилей Qt и цвета светлой и тёмной тем
   * - ``gm_hub.ui.gm_window`` и ``gm_hub.ui.player_window``
     - кабинеты Мастера (6 вкладок) и Игрока (3 вкладки)

База данных
-----------

В базе шесть таблиц (структура — в приложении А технического задания).
Все даты хранятся строкой ``ГГГГ-ММ-ДД ЧЧ:ММ``.

.. list-table::
   :header-rows: 1
   :widths: 22 78

   * - Таблица
     - Что хранит
   * - ``Users``
     - пользователи: ФИО, логин, хэш пароля с солью, роль (``GM`` или ``PLAYER``)
   * - ``Characters``
     - персонажи Игроков: имя, раса, класс, уровень 1–20, предыстория
   * - ``Games``
     - игровые сессии Мастера: название, дата, лимит мест, статус (``PLANNED``, ``CLOSED``, ``CANCELLED``), итоги
   * - ``Game_Signups``
     - заявки персонажей на сессии: статус (``PENDING``, ``CONFIRMED``, ``REJECTED``), комментарий, причина отказа; пара «сессия — персонаж» уникальна
   * - ``Game_Notes``
     - сюжетная заметка к сессии (одна на сессию)
   * - ``World_Notes``
     - записи базы знаний мира Мастера: категории «Лор», «NPC», «Локации»

Связи «один ко многим»: пользователь — персонажи и сессии; сессия — заявки;
персонаж — заявки. Число свободных мест не хранится, а считается по формуле
**F = M − C**, где M — лимит мест, C — число подтверждённых заявок.

Хранение настроек и журнал
--------------------------

Файл ``settings.json`` и файл ``gm_hub.log`` лежат рядом с базой данных
(в корне проекта, а у собранной программы — рядом с ``GameMasterHub.exe``).
В журнал попадают только непредвиденные ошибки; все ожидаемые ошибки ввода
показываются пользователю в окне и в журнал не пишутся.
