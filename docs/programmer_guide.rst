Руководство программиста
========================

Руководство описывает, как использовать слой бизнес-логики «Game Master Hub»
из своего кода (скрипты, тесты, другой интерфейс). Составлено по образцу
структуры руководства программиста из ЕСПД.

1. Назначение и условия применения программ
-------------------------------------------

1.1. Назначение
~~~~~~~~~~~~~~~

Пакеты ``gm_hub.db`` и ``gm_hub.logic`` реализуют всю работу с данными и
правилами системы и не зависят от интерфейса. Их можно вызывать без окон:
из автотестов, из скрипта наполнения базы (``seed.py``) или из другого
интерфейса (например, консольного).

1.2. Условия применения
~~~~~~~~~~~~~~~~~~~~~~~

* Python 3.10 или новее (разработка и проверка — на Python 3.13);
* модуль ``sqlite3`` из стандартной библиотеки (отдельные библиотеки для
  логики не нужны; PySide6 нужен только пакету ``gm_hub.ui``);
* запуск из корня проекта, чтобы пакет ``gm_hub`` находился при импорте.

2. Характеристика программы
---------------------------

2.1. Основные характеристики
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

* **Хранение данных:** файл SQLite; шесть таблиц, внешние ключи включены
  (``PRAGMA foreign_keys = ON``), даты — строки ``ГГГГ-ММ-ДД ЧЧ:ММ``.
* **Транзакции:** каждое изменение выполняется в ``with conn:`` — при ошибке
  изменения не сохраняются частично.
* **Безопасность:** запросы параметризованы; пароль хранится как хэш с солью
  (``hashlib``), в открытом виде не хранится.
* **Права:** функции получают текущего пользователя и сами проверяют роль и
  владельца данных (Мастер видит только свои сессии, заявки и заметки).
* **Скорость:** все операции — одиночные запросы к локальному файлу, отклик на
  действие не превышает долей секунды.

2.2. Особенности
~~~~~~~~~~~~~~~~

* первым аргументом любой функции логики является подключение ``conn``,
  вторым (если нужно) — пользователь ``user`` (строка из ``login_user``);
* результат запроса — ``sqlite3.Row``: к полям обращаются по имени
  (``game["title"]``);
* число свободных мест всегда считается функцией ``games.free_seats`` по формуле
  F = M − C и в БД не хранится.

3. Обращение к программе
------------------------

3.1. Подключение и создание таблиц
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: python

   from gm_hub.db.database import connect, init_db

   conn = connect("demo.db")   # файл создаётся при первом обращении
   init_db(conn)               # таблицы создаются из schema.sql

3.2. Пример: полный путь заявки
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: python

   from gm_hub.logic import auth, characters, games, signups

   # два пользователя
   auth.register(conn, "Агыг", "agyg", "1234", "1234", "GM")
   auth.register(conn, "Денисов Глеб", "gleb", "1234", "1234", "PLAYER")
   gm = auth.login_user(conn, "agyg", "1234")
   player = auth.login_user(conn, "gleb", "1234")

   # Мастер публикует сессию на 3 места (дата — в будущем)
   game_id = games.save_game(
       conn, gm, "Шахта Эхо", "Спуск на нижние ярусы", "01.01.2031", "18:00", 3
   )

   # Игрок создаёт персонажа и подаёт заявку
   hero = characters.save_character(
       conn, player, "Пип", "Полурослик", "Плут", 4, "Вырос в Сером Броде"
   )
   signup_id = signups.create_signup(conn, player, game_id, hero, "Приду к 18:15")

   # Мастер подтверждает заявку; свободных мест становится 2
   signups.confirm_signup(conn, gm, signup_id)
   game = games.get_game(conn, game_id)
   print(games.free_seats(game["max_players"], game["confirmed"]))   # 2

3.3. Основные функции
~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 38 62

   * - Функция
     - Назначение
   * - ``auth.register``, ``auth.login_user``
     - регистрация (проверяет пароль, роль, занятость логина), вход
   * - ``games.save_game``, ``cancel_game``, ``delete_game``
     - создание и изменение, отмена, удаление отменённой сессии
   * - ``games.list_games``, ``get_game``
     - список сессий по статусу (с числами ``confirmed`` и ``pending``), одна сессия
   * - ``signups.create_signup``, ``withdraw_signup``
     - подача и отзыв заявки Игроком
   * - ``signups.confirm_signup``, ``reject_signup``
     - решение Мастера; подтверждение проверяет лимит мест
   * - ``signups.queue_positions``
     - номера заявок в листе ожидания
   * - ``characters.save_character``, ``delete_character``
     - карточки персонажей, запрет удаления при активных заявках
   * - ``notes.save_game_note``, ``save_world_note``
     - заметки к сессиям и база мира, поиск
   * - ``games.master_stats``
     - статистика Мастера

Полный список с описанием параметров — в разделе :doc:`api`.

4. Входные и выходные данные
----------------------------

4.1. Входные данные
~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Данные
     - Формат
   * - дата сессии
     - строка ``ДД.ММ.ГГГГ`` и отдельно время ``ЧЧ:ММ`` (в БД — ``ГГГГ-ММ-ДД ЧЧ:ММ``); дата не в прошлом
   * - лимит мест
     - целое число больше нуля (строка или число)
   * - уровень персонажа
     - целое число от 1 до 20
   * - роль
     - ``"GM"`` (Мастер) или ``"PLAYER"`` (Игрок)
   * - пароль
     - не короче 4 символов, повтор должен совпадать

4.2. Выходные данные
~~~~~~~~~~~~~~~~~~~~

Функции возвращают id созданной записи, ``sqlite3.Row`` или список строк, число
затронутых записей либо ``None``. Экспорт состава сессии
(``signups.export_participants``) записывает файл CSV в кодировке UTF-8 с
меткой BOM и разделителем «;» — он корректно открывается в Excel.

4.3. Кодирование данных
~~~~~~~~~~~~~~~~~~~~~~~

Статусы сессий: ``PLANNED``, ``CLOSED``, ``CANCELLED``; статусы заявок:
``PENDING``, ``CONFIRMED``, ``REJECTED``; категории заметок: ``LORE``, ``NPC``,
``LOCATION``. Русские названия статусов — в словарях ``games.STATUS_NAMES`` и
``signups.STATUS_NAMES``.

5. Сообщения
------------

Все ошибки правил — исключения двух классов (модуль ``gm_hub.logic.errors``):

* ``ValidationError(field, message)`` — неверный ввод или нарушение правила;
  поле ``field`` — название поля формы, ``message`` — текст для пользователя;
* ``AccessError`` — действие недоступно роли или чужие данные.

.. code-block:: python

   from gm_hub.logic.errors import ValidationError

   try:
       signups.confirm_signup(conn, gm, signup_id)
   except ValidationError as error:
       print(error.field, error.message)

Перечень текстов сообщений и действий пользователя — в разделе
:doc:`operator_guide` (пункт «Сообщения оператору»).
