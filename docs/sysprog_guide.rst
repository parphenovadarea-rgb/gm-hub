Руководство системного программиста
===================================

Составлено по ГОСТ 19.503-79. Руководство описывает установку, настройку и
проверку работоспособности «Game Master Hub» на компьютере.

1. Общие сведения о программе
-----------------------------

1.1. Назначение и функции
~~~~~~~~~~~~~~~~~~~~~~~~~

Программа организует запись на настольные ролевые игры: публикация игровых
сессий с лимитом мест, заявки Игроков, подтверждение заявок Мастером, сюжетные
заметки и база знаний мира. Подробно функции описаны в разделе
:doc:`functionality`.

1.2. Технические и программные средства
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Средство
     - Требование
   * - Операционная система
     - Windows 10 или 11 (64 бита)
   * - Для запуска собранной программы
     - ничего дополнительно не нужно (всё внутри папки программы)
   * - Для запуска из исходного кода
     - Python 3.13, библиотека PySide6 (файл ``requirements.txt``)
   * - Для разработки
     - инструменты из ``requirements-dev.txt``: black, flake8, pre-commit, PyInstaller, Sphinx
   * - Оперативная память и диск
     - около 75 МБ памяти сразу после запуска; около 70 МБ на диске
   * - Сеть
     - не нужна; программа работает на одном компьютере

2. Структура программы
----------------------

Программа состоит из трёх уровней (подробно — в разделе :doc:`architecture`):

* ``gm_hub.ui`` — окна и оформление (PySide6);
* ``gm_hub.logic`` — правила системы и проверки;
* ``gm_hub.db`` — подключение к SQLite и описание таблиц.

Связи с другими программами: Excel открывает файл CSV, который создаёт
кнопка «Сохранить список»; других интеграций нет. Данные хранятся в файле
``gm_hub.db``, настройки компьютера — в ``settings.json``, ошибки — в
``gm_hub.log`` (все три файла лежат рядом с программой).

3. Настройка программы
----------------------

3.1. Установка собранной программы
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. Скопируйте программу (файл ``GameMasterHub.exe``; если собрано папкой —
   всю папку вместе с ``_internal``) в любое место, где у пользователя есть
   право записи (не в ``Program Files``): рядом с программой создаются файлы
   данных.
2. Для начала с чистого листа не копируйте ``gm_hub.db`` — при первом запуске
   откроется регистрация первого пользователя. Чтобы показать программу на
   готовых данных, положите рядом демонстрационную ``gm_hub.db``.
3. Запустите ``GameMasterHub.exe``.

3.2. Запуск из исходного кода
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: text

   py -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements-dev.txt
   py main.py

3.3. Демонстрационные данные
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Скрипт ``seed.py`` создаёт БД с двумя Мастерами, шестью Игроками, персонажами,
сессиями и заявками во всех статусах (пароль у всех пользователей — ``1234``).
Чтобы не затронуть рабочую базу, задайте другой файл:

.. code-block:: text

   py seed.py demo.db

.. warning::

   Запуск ``py seed.py`` без аргумента удаляет рабочий файл ``gm_hub.db``.

3.4. Сборка исполняемого файла
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Сборка выполняется скриптами из корня проекта (нужно виртуальное окружение
``.venv`` с установленным ``requirements-dev.txt``):

.. code-block:: text

   build.bat           один файл dist\GameMasterHub.exe (около 36 МБ)
   build_folder.bat    папка dist\GameMasterHub (около 70 МБ, запуск быстрее)

Оба скрипта запускают PyInstaller и убирают из сборки лишнее (сетевой модуль
Qt). Файл ``GameMasterHub.exe`` при каждом старте распаковывается во
временную папку, поэтому стартует примерно за 1 секунду; папка запускается за
0,3–0,8 с, но папка ``_internal`` должна лежать рядом с файлом. Если на
конкретном компьютере одиночный файл запускается слишком медленно, выдайте
папку. Проверенный порядок выдачи: собрать, положить рядом демонстрационную
базу ``gm_hub.db`` и инструкцию, заархивировать, распаковать архив в другую
папку и запустить оттуда.

3.5. Настройки на компьютере
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Файл ``settings.json`` создаётся программой сам и содержит тему, запомненные
логины, последнюю вкладку, размер окон и признак «Крупный текст». Чтобы
сбросить настройки, закройте программу и удалите этот файл — данные в базе не
пострадают.

4. Проверка программы
---------------------

4.1. Способы проверки
~~~~~~~~~~~~~~~~~~~~~

.. code-block:: text

   py -m unittest discover -s tests    # автотесты (правила, БД, окна)
   py -m coverage run -m unittest discover -s tests
   py -m coverage report               # покрытие кода тестами
   py -m flake8 gm_hub main.py tests   # проверка стиля кода
   py -m black --check gm_hub main.py tests   # проверка форматирования

Автотесты разделены на группы:

* модульные тесты правил (``test_auth``, ``test_games``, ``test_signups`` и
  другие) — 17 сценариев пункта 6.1 технического задания;
* тесты граничных условий и безопасности (``test_edge``): неверные даты,
  лимиты, уровни, права ролей, SQL-инъекции в логине, заметках и поиске,
  хэширование паролей, внешние ключи, откат транзакции;
* интеграционные тесты окон (``test_ui``, ``test_ui_more``): вход, формы,
  клавиши, заявка от Игрока до решения Мастера, все вкладки, профиль,
  справка, темы; окна проверяются без экрана (``QT_QPA_PLATFORM=offscreen``).

Покрытие кода тестами — около 92 % (логика — 99–100 %, окна — 80–100 %).

4.2. Контрольные примеры
~~~~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 8 42 50

   * - №
     - Действия
     - Ожидаемый результат
   * - 1
     - запустить программу на пустой папке
     - открывается окно «Регистрация»
   * - 2
     - зарегистрировать Мастера, создать сессию на 2 места
     - сессия видна в «Расписании», свободно 2 из 2
   * - 3
     - зарегистрировать Игрока, создать персонажа, подать заявку на сессию
     - заявка «На рассмотрении», у Мастера вкладка «Заявки (1)»
   * - 4
     - подтвердить заявку, подать и подтвердить вторую, подать третью
     - третья заявка «№1 в очереди», кнопка «Подтвердить» неактивна
   * - 5
     - у Мастера отменить сессию
     - заявки на рассмотрении отклонены с причиной «Сессия отменена»
   * - 6
     - второй Мастер открывает свой кабинет
     - чужих сессий, заявок и заметок не видит

4.3. Результаты проверки
~~~~~~~~~~~~~~~~~~~~~~~~

На момент выпуска версии 1.0 проходят все автотесты, замечаний flake8 и black
нет, окно собранной программы открывается меньше чем за секунду. Замеры на
демонстрационных данных: кабинет Мастера открывается за 0,3 с, переключение
вкладки занимает не больше 0,04 с, изменение размера окна — 0,02 с.

5. Дополнительные возможности
-----------------------------

* демонстрационная база (``seed.py``);
* экспорт состава сессии в CSV (для печати перед игрой);
* тёмная тема и крупный текст — включаются пользователем, на настройку
  системы не влияют.

6. Сообщения системному программисту
------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 38 62

   * - Сообщение или признак
     - Причина и действие
   * - «Ошибка базы данных: Операция не выполнена: …»
     - файл ``gm_hub.db`` повреждён, занят другой программой или нет прав на запись; закрыть другие копии программы, проверить права на папку, восстановить базу из копии
   * - «Непредвиденная ошибка … записаны в файл gm_hub.log»
     - ошибка в коде программы; открыть ``gm_hub.log`` — в нём время и трассировка вызовов — и передать разработчику
   * - окно не открывается, «could not find the Qt platform plugin»
     - в папке программы нет ``_internal`` или он повреждён; скопировать папку целиком
   * - программа открывается за экраном или слишком маленькой
     - удалить ``settings.json`` (сбросит размер окон)
   * - нет файла ``gm_hub.log``
     - ошибок не было либо нет права записи в папку программы
